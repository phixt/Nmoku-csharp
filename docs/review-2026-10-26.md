## 二、P0 — 必须优先处理

### P0-1 存档槽位以「档 Id」而非槽位号为主键 → 复制/导入会让原槽从存档列表消失【数据丢失·已发布功能可达】

- `src/Nmoku.Game/FileSystemStorageAdapter.cs:26` `private readonly Dictionary<string, SlotMeta> _byId = [];`
  —— **主键是 Id，不是槽位号**
- `:88` `_byId[id] = meta;` —— 同 Id 写入**覆盖**原槽索引项
- `:71` `GetIndexAsync() => [.. _byId.Values];` —— 索引表因此只剩一条
- `src/Nmoku.Game/GameStore.cs:414` `Saves.SaveAsync(index, package.Data, package.WinLength)` ——
  导入**保留原 Id**（CHANGELOG「导入原档保真」的既定语义）

**复现路径**：存档菜单 → 槽 0「复制」→ 槽 1「填写」→ **槽 0 从存档列表消失**（磁盘 blob 仍在，
index.json 已无该槽）。删除任一槽会连带删掉共享的同一 blob 文件。

`Main.cs` 的 `AutotestSaveAlignment` 恰好制造了这个状态却只断言内存态，掩盖了问题。

**修法**：索引改以槽位号为主键（`Dictionary<int, SlotMeta>`），blob 文件名带槽位前缀。
⚠️ 与「导入保真 id」存在语义冲突 → **需人类拍板**。

### P0-3 BGM 淡出 ε 停滞 → 无头自测间歇性红，修复只在未合并分支

`src/Nmoku.Game/Audio/SampleMusicEngine.cs` 的 `_Process`：淡出步进若落入 `(0, 1e-5]` 残差，
下一帧 `Mathf.IsEqualApprox(Lin, Target)` 判等 → 跳过步进 → 而停播判据要求 `Lin <= 0` 严格成立
→ **轨位永挂 -80dB 静默循环**。

审查者实测 8 轮全量自测失败 2 次，失败步骤每次不同（`m5-audio-settings: FAIL mute-on` /
`m5-bgm-crossfade: FAIL p2`），随后连绿——典型的概率性 bug。CI 的 `godot-smoke` 门禁
（`ci.yml:66`）因此随时可能随机变红。

**决定性证据**：未合并分支 `bgm-engine` 的 HEAD 提交 `cbddfe3` 正是此修复，其提交信息自陈：
「步进落入 0~1e-5 被判等早退卡住而停播判定要求严格≤0（**非确定性，同码多轮自测有绿有红，少轮测不出**）」。

> **✅ 已于修复批 1 修复**（commit `e10cd51`）：产出残差的同一帧钳到精确 0；修复后 4 轮全绿。

### P0-5 `CameraRig._distanceOverride` 使公式距离永不重算，且现有测试靠 1 ulp 假绿

`src/Nmoku.Core/Camera/CameraRig.cs:71-74`：

```csharp
double distance = _distanceOverride is { } overridden
    ? Math.Clamp(overridden, minDist, maxDist)
    : CameraMath.ComputeDistance(targetDiagonal, fov, aspect);   // ← 构造后成为死代码
_distanceOverride = distance;                                     // ← 无条件写回
```

构造时（`:32`）已写入公式距离，此后**任何** `Update` 都走 clamp 分支。实测：视口宽高比 16:9→0.5 后
`Target.Distance` 仍为 31.6904，而公式值应为 **57.1307**。窗口缩放/最大化后 3D 盘不再重新贴合画面。

而 `tests/Nmoku.Core.Tests/CameraRigTests.cs:37-46`（`Update_AspectChange_RecomputesDistanceAndKeepsYaw`）
**靠 3.55e-15 的浮点毛刺通过**——CI 绿灯是假象。

**修法**：把「用户缩放」存成倍率或相对偏移而非绝对距离；或区分变更源（spacing 变更保留用户缩放、
aspect 变更强制重算公式距离）。同时把断言改成对公式值的等值断言。

- `SaveManager.GetLatestIndex()` 在唯一存档 timestamp=0 时返回 -1（`latestTs` 初值 0 + 严格 `>`）。

## 六、亮点（值得保留的设计）

1. **数学单一事实源达成**：3D 无第二套相机数学（`CameraMath`/`CameraRig` 全在 Core），坐标映射全走
   `CoordMapper.LogicalToWorld` → 无漂移风险。
2. **M4 相机事故是结构性根治**：弃用 `SubViewportContainer` + 自绘 `ViewportHost`（最小尺寸恒零）
   → 回环路径被切断而非参数调优。
3. **胜负判定是增量式的**：只在落子点做 13 方向双向扫描（O(13×winLength)），无 O(n³) 全盘扫描。
4. **13 方向逐值逐序对齐源**，并有参数化用例锁住全部 13 向。
5. **SWAP2 严格落实 B1/B2**，swap/pass 两条分支各有全流程端到端测试。
6. **「首中即吞」在所有输入路径成立**（有序动作表 + `Allows` 门控 + `SetInputAsHandled`），
   M4R 的 ESC/R 双触发坑被结构性根除。
7. **Overlay 契约经得起推敲**：先关窗再回调 → 恰好一次且回调内可再开窗；toast 用
   `RemoveChild`+`QueueFree` 规避 77GB 事故根因。
8. **AI 候选集用 `HashSet` 替代源的 `x*10000+y*100+z` 键**，规避 boardSize≥100 的键碰撞 ——
   对源的实质性改进且无行为差异。
9. **AudioBake 的「源参数精确复刻」经逐行比对属实**（22050Hz、5ms/60ms 包络、0.7 缩放、滑音只作用于
   首频、方/三/正弦公式逐字一致）。
10. **i18n 用 zh-CN 原文作 gettext 键** → Core 的 Text 常量零改动，且有反射完备性测试做「防漏译」。
11. **预开始页与主对局零状态共享**：独立 `Board` 实例 + 纯函数 `AuxScan` + 无静态单例。
12. **形变插值完全可逆**：全部由归一化进度驱动 → 反向即回起点，无「被打断卡中间态」。
13. **断言强度高于平均**：状态机 7×11 全组合穷举、13 方向全遍历、损坏档逐层维度校验、
    相机数学**独立复算而非抄实现**；无 `Assert.True(true)`、无 sleep/墙钟依赖（除 1 处 `<100ms`）。
